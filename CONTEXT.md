# CI/CD Node Delivery

Учебный контекст доставки Node-приложения в публичную среду через контейнер, пайплайн и деплой.

## Language

**Приложение**:
Node-процесс, который слушает `PORT` и работает с базой по `DATABASE_URL`.
_Avoid_: сервис, бэкенд, API (как синонимы того же целого), контейнер

**Образ**:
Неизменяемый артефакт контейнера — результат сборки Приложения для запуска.
_Avoid_: контейнер (запущенный экземпляр), пакет, билд (как синоним артефакта)

**Реестр**:
Хранилище Образ'ов (например GHCR или Docker Hub), откуда их забирают для Деплоя.
_Avoid_: хостинг, деплой, Docker Hub (как имя понятия, а не конкретного продукта)

**Пайплайн**:
Автоматическая цепочка в CI (проверки → сборка → публикация Образа в Реестр).
_Avoid_: деплой, Actions (как имя понятия), скрипт

**Деплой**:
Запуск конкретной версии Образа на хостинге так, что Приложение доступно по публичному URL.
_Avoid_: публикация образа, релиз (без уточнения), выкат «куда угодно»)

**Миграция**:
Изменение схемы базы, которое должно быть применено до (или в момент) старта Приложения на новой версии.
_Avoid_: сид, инициализация БД, «просто поднять Postgres»

**Item**:
Единственная бизнес-сущность Приложения: запись с идентификатором, заголовком и временем создания.
_Avoid_: todo, note, entity, ресурс

**Staging**:
Среда Деплоя для проверки Образ'а до Production; не публичный «боевой» контур пользователя.
_Avoid_: dev, test, preview (без уточнения)

**Production**:
Среда Деплоя, с которой пользователи работают по основному публичному URL.
_Avoid_: прод, live, «сервер»

**Релиз**:
Намеренное продвижение уже опубликованного Образа в Production (через tag `v*` или ручной dispatch).
_Avoid_: деплой (любой), публикация в Реестр, merge в main

**Rollback**:
Деплой ранее известного Образа (digest / `sha-…`) в Production без отката Миграций вниз.
_Avoid_: hotfix, revert, «откат миграций»
